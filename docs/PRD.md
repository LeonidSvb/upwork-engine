# Upwork AI Intake & Triage (MVP)

Энд‑ту‑энд пайплайн: Volna вебхук → базовый AI‑фильтр (RU, бинарный) → сохранение raw в Supabase → скоринг и саммари тем же промптом (структурированный JSON) → генерация cover letter по .md шаблону с персонализацией → Slack‑уведомления по порогу → фронтенд на Vercel (фильтры: скоринг/дата, просмотр/правка промптов и шаблонов). Без усложнений, без auth, один пользователь.

---

## Users & Value

- **Primary user / persona:** Соло‑разработчик/агент (вы), ведущий AI‑автоматизацию и отклики на Upwork
- **Jobs-to-be-done (JTBD):**
  - Когда приходит новая вакансия из Volna, хочу мгновенно понять «брать/не брать», чтобы сэкономить время.
  - Когда вакансия релевантна, хочу увидеть оценку, краткое резюме и черновик cover letter, чтобы быстро податься.

---

## Success Metrics

- **Primary Goal:** Сократить ручной тряж и ускорить подготовку качественных откликов.
- **Success Criteria:** Среднее время на обработку лида ≤ 1 мин; ≥ 5 релевантных лидов/день; ≥ 80% попадание фильтра «да» в реально интересные.

## Scope

| Must‑have (MVP) | Nice‑to‑have (Later) | Explicitly Out (Not now) |
| --------------- | -------------------- | ------------------------ |
| 1 вебхук из Volna в n8n | Несколько вебхуков и маршрутизация | Мульти‑аккаунты и роли |

| Базовый AI‑фильтр (RU) «да/нет», неуверенность = «нет» | Telegram/WhatsApp уведомления | Сложная аналитика/дашборды |
| Простая дедупликация по `jobId`/ссылке | A/B‑тесты промптов, версионирование | Экспорт/импорт данных |
| Скоринг в том же промпте (структурированный JSON) | Доп. факторы/веса из UI | Мульти‑LLM фоллбеки |
| Саммари (RU) в структуре JSON | История версий вакансий | Сложная авторизация |
| Генерация cover letter по .md шаблону + персонализация | Автогенерация артефактов |  |
| Slack уведомление при `score >= threshold` | Тихие часы/агрегация |  |
| Фронт на Vercel: список, фильтры по скорингу/дате, просмотр/редактирование промптов и шаблонов (.md в Storage) | Просчёт ROI/стоимости по вакансиям |  |
| Мини‑панель: просмотр суммарных токен‑затрат | | |

- **Definition of Done (MVP):**
  - [ ] Приходящий из Volna payload попадает в Supabase (raw) с идемпотентностью.
  - [ ] LLM возвращает строго валидный JSON со схемой: decision, score, summary, meta.
  - [ ] Данные скоринга/резюме сохраняются и видны на фронте; фильтры по score/date работают.
  - [ ] Генерируется черновик cover letter из .md шаблона + ваших данных; доступно редактирование.
  - [ ] Slack уведомления отправляются только при score ≥ порога (настраиваемый threshold).
  - [ ] Промпты/шаблоны редактируются во фронте и хранятся как .md в Supabase Storage.

## Tech Stack

### Frontend:
- Next.js (App Router) + TypeScript, деплой на Vercel
- Tailwind CSS (минимальный UI), без auth (один пользователь)
- Прямое подключение к Supabase (DB/Storage) для чтения/записи промптов/шаблонов

### Backend:
- n8n (обработка вебхука, вызовы OpenAI, запись в Supabase, отправка Slack)
- OpenAI (mini‑модель, RU‑промпт, строгий JSON‑ответ)
- Slack Incoming Webhook (уведомления по порогу)
- Опционально позже: Supabase Edge Functions для тяжёлых мест

### Database:
- Supabase Postgres + Storage
  - Таблица `jobs` (упрощённо, single‑table для MVP):
    - `id` (uuid, pk), `source_job_id` (text, unique), `source_url` (text), `created_at` (timestamptz)
    - `raw` (jsonb)
    - `decision` (text: 'yes'|'no'), `score` (int), `summary_json` (jsonb), `cover_letter_md` (text)
    - `notified_at` (timestamptz), `model` (text), `prompt_version` (text), `cost_tokens` (int), `cost_usd` (numeric)
  - Storage buckets:
    - `prompts/` — .md файлы промптов (фильтр/скоринг/саммари)
    - `templates/` — .md шаблоны cover letter

## Допущения (MVP)

- Один вебхук на старте; неуверенные кейсы трактуем как «нет».
- Дедупликация: уникальный `source_job_id` (или hash `title+url` если id нет).
- Все персональные/PII «забиваем» для MVP; храним как пришло в raw.
- Язык вывода и промптов — русский.
- Bali TZ (UTC+8) используется для отображения дат/фильтрации.
- Токены дешёвые; показываем суммарную оценку в мини‑панели.
